# Север — социальная сеть

Стек: **React (Vite)** + **Node/Express** + **SQLite** (может быть легко заменён на PostgreSQL).

## Возможности
- Регистрация и вход (JWT-токены, пароли хэшируются)
- Лента постов, лайки/реакции, комментарии
- Подписки (follow/unfollow)
- Сообщества (создание, вступление, посты внутри)
- Личные сообщения (в реальном времени через WebSocket)
- Профили пользователей с аватаром
- Загрузка файлов (аватар/изображения в постах)
- Постраничная навигация в ленте и профиле (10 постов на страницу)
- Пометка «NSFW (18+)» для постов и сообщений (контент размыт до нажатия)

## Безопасность
- **Двухфакторная аутентификация (2FA)** через TOTP (приложение-аутентификатор:
  Google Authenticator, Aegis, 1Password и т.п.) — работает офлайн, без SMS и почты.
  10 одноразовых резервных кодов хранятся только в виде SHA-256 хэшей.
  Для администраторов 2FA обязательна (отключение запрещено).
- **Email не раскрывается**: чужие пользователи видят только логин/имя; email и статус 2FA
  отдаются только владельцу аккаунта (`/auth/me`, `/users/me`).
- **Сессии**: каждый вход — отдельная сессия с IP и user-agent. Смена пароля, включение/отключение
  2FA завершают все остальные сессии. Есть «выход со всех устройств» и просмотр активных сессий.
- **Ограничение частоты запросов** на регистрацию, вход и код 2FA (по IP) — защита от перебора.
- **Смена email/логина требует текущий пароль.** Смена пароля завершает чужие сессии.
- **Журнал безопасности**: входы (в т.ч. неудачные и с 2FA), смена пароля, включение/отключение 2FA
  и т.п. — виден владельцу в «Настройки → Безопасность».
- Базовые заголовки безопасности (no-sniff, DENY во фреймах, referrer same-origin и т.п.).
- Секрет JWT задаётся в `server/.env` (`JWT_SECRET`) — смените его на свой.

> ⚠️ После первого запуска новой версии все ранее выданные токены аннулируются —
> пользователям придётся один раз войти заново (одноразовая миграция безопасности).

## Запуск
```bash
npm install          # поставить корневые зависимости (concurrently)
npm run setup        # установить зависимости server + client
npm run dev           # запустить сервер (:4000) и клиент (:5173)
```

Открыть http://localhost:5173

## Публикация через cloudpub (https)
Сайт работает через локальный хостинг и туннель **cloudpub** (Cloudflare). Обязательно:
1. В `server/.env` укажите домен туннеля в `CLIENT_ORIGIN` (можно несколько через запятую),
   например: `CLIENT_ORIGIN=http://localhost:5173,https://sever.example.cloudpub.ru`
2. Поменяйте `JWT_SECRET` на свой секрет.
3. Включите 2FA для администратора.

## База данных
`npm run db` (или `npm run db:reset`) полностью очищает БД: удаляет всех пользователей,
посты, диалоги и т.п. Тестовые данные не создаются — это чистая социальная сеть.
Администратор не задан (для доступа к админ-панели выставьте `is_admin = 1` вручную).

## Переключение на PostgreSQL
SQLite используется только ради запуска без внешней БД. Схема портативна:
в `server/src/db.js` замените подключение на `new pg.Pool(...)` и поменяйте
маппинг типов. Таблицы уже спроектированы как в PostgreSQL.
